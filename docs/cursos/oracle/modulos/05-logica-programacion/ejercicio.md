## Ejercicio 3: Búsqueda (Salario máximo por departamento)

**Dificultad:** ⭐⭐ Intermedio

**Enunciado:** Encuentra el empleado con el salario más alto del departamento 80. Debes implementar la búsqueda manualmente (sin usar `MAX()` en SQL) con un bucle `LOOP` + `EXIT WHEN`.

**Requisitos:**
- Usar un cursor explícito con `OPEN`, `FETCH`, `CLOSE`
- Usar `LOOP` con `EXIT WHEN` (condición: `c_emp%NOTFOUND`)
- Comparar cada salario con el máximo encontrado hasta el momento
- Almacenar nombre, apellido y salario del empleado con mayor salario
- Mostrar el resultado

**Estructura esperada:**
```plsql
OPEN c_emp;
LOOP
  FETCH c_emp INTO v_...;
  EXIT WHEN c_emp%NOTFOUND;
  -- comparar y actualizar si es mayor
END LOOP;
CLOSE c_emp;
```

## Ejercicio 6: Algoritmo completo (Sistema de préstamos de biblioteca)

**Dificultad:** ⭐⭐⭐ Avanzado

**Enunciado:** Implementa un sistema de préstamos de biblioteca usando el esquema HR como simulación. Los empleados serán los "miembros" de la biblioteca y los departamentos simularán "libros" disponibles para préstamo.

**Reglas de negocio:**

1. Un miembro (empleado) puede tener como máximo **3 préstamos activos**
2. Cada préstamo tiene una **fecha de devolución estimada** → fecha de préstamo + 14 días
3. Si el miembro ya tiene 3 préstamos activos, se debe rechazar el nuevo préstamo con un mensaje de error
4. Si el miembro es válido, se registra el préstamo en una tabla temporal

**Partes del ejercicio:**

### 6.1 Crear tabla temporal

```sql
CREATE GLOBAL TEMPORARY TABLE prestamos_temp (
  prestamo_id    NUMBER GENERATED BY DEFAULT AS IDENTITY,
  miembro_id     NUMBER(6),
  libro_dept_id  NUMBER(4),
  fecha_prestamo DATE,
  fecha_devolucion DATE,
  activo         VARCHAR2(1) DEFAULT 'S'
) ON COMMIT PRESERVE ROWS;
```

### 6.2 Implementar el procedimiento principal

Implementa un bloque PL/SQL anónimo que:

1. Solicite (simule con variables) un `miembro_id` y un `libro_dept_id`
2. Valide que el miembro existe en `employees`
3. Valide que el departamento existe en `departments`
4. Cuente los préstamos activos del miembro (`activo = 'S'`)
5. Si tiene 3 o más → mostrar mensaje: `"Error: El miembro XXX ya tiene 3 préstamos activos"`
6. Si es válido → insertar el préstamo con fechas calculadas
7. Mostrar confirmación: `"Préstamo registrado. Devolución estimada: DD/MM/YYYY"`

### 6.3 Probar el sistema

Inserta manualmente 3 préstamos para un mismo miembro y luego intenta un cuarto préstamo para verificar que el sistema lo rechaza correctamente.

**Requisitos:**
- Usar `SELECT COUNT(*)` para contar préstamos activos
- Usar `SYSDATE` para la fecha de préstamo
- Calcular fecha de devolución: `SYSDATE + 14`
- Manejar el caso de que el miembro no exista
- Manejar el caso de que el departamento no exista
- Limpiar la tabla temporal al finalizar

**Estructura del bloque:**

```
DECLARE
  -- variables para miembro, departamento, conteo, etc.
BEGIN
  -- Paso 1: Validar miembro
  -- Paso 2: Validar departamento
  -- Paso 3: Contar préstamos activos
  -- Paso 4: Decidir si permitir o rechazar
  -- Paso 5: Insertar si es válido
  -- Paso 6: Mostrar resultado
EXCEPTION
  WHEN NO_DATA_FOUND THEN
    DBMS_OUTPUT.PUT_LINE('Error: Miembro o departamento no encontrado');
END;
```

- Mostrar la serie en una sola línea, separada por comas

**Reflexión:** ¿Qué patrón de lógica de programación representa Fibonacci (acumulador doble)?

## Ejercicio 10: Números primos — Nested loops y optimización

**Dificultad:** ⭐⭐⭐ Avanzado

**Enunciado:** Encuentra todos los números primos entre 2 y 100. Un número es primo si solo es divisible por 1 y por sí mismo.

**Requisitos:**
- Usar un `FOR` externo para recorrer los números del 2 al 100
- Usar un `FOR` interno para verificar divisibilidad (desde 2 hasta la raíz cuadrada del número)
- Usar una variable booleana `v_es_primo` controlada con `EXIT WHEN`
- Optimizar: no es necesario probar divisores hasta n-1, basta hasta `SQRT(n)`
- Mostrar los primos encontrados, 10 por línea

**Algoritmo (pseudocódigo):**
```
PARA n DESDE 2 HASTA 100:
  es_primo = TRUE
  PARA d DESDE 2 HASTA SQRT(n):
    SI n MOD d = 0 ENTONCES
      es_primo = FALSE
      SALIR DEL LOOP INTERNO  -- EXIT WHEN
    FIN SI
  FIN PARA
  SI es_primo ENTONCES
    Mostrar n
  FIN SI
FIN PARA
```

**Reflexión:** ¿Por qué alcanza con probar divisores hasta `SQRT(n)` en vez de `n-1`? ¿Qué patrón es `EXIT WHEN` dentro de un nested loop?
