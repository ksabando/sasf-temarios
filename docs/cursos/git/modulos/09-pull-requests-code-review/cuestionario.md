# Cuestionario - Módulo 09

1. ¿Qué es un Pull Request?
   R: Una solicitud para fusionar cambios de una rama a otra, con revisión previa.

2. ¿Cuál es la diferencia entre un PR normal y un Draft PR?
   R: Un Draft PR indica que no está listo para revisión; no puede fusionarse.

3. ¿Qué hace `gh pr create`?
   R: Crea un Pull Request desde la terminal.

4. ¿Cuáles son los tres tipos de revisión en `gh pr review`?
   R: Approve, comment, request-changes.

5. ¿Qué es un squash merge?
   R: Comprime todos los commits de la rama en un único commit al fusionar.

6. ¿Qué ventaja tiene el rebase merge sobre el merge commit?
   R: Genera una historia lineal sin commits de merge.

7. ¿Qué es branch protection?
   R: Reglas que protegen una rama (requisitos para fusionar PRs).

8. ¿Por qué es recomendable que los PRs sean pequeños?
   R: Facilitan la revisión, reducen errores y se integran más rápido.

9. ¿Qué son los checks en un PR?
   R: Validaciones automáticas (tests, lint, build) ejecutadas por CI.

10. ¿Qué hace `gh pr checkout 42`?
    R: Descarga localmente el PR número 42 para revisarlo.
