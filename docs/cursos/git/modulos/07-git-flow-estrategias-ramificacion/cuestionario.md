# Cuestionario - Módulo 07

1. ¿Cuáles son las dos ramas principales en Git Flow?
   R: `main` (producción) y `develop` (integración).

2. ¿Desde qué rama nace una `feature` en Git Flow?
   R: Desde `develop`.

3. ¿Cuál es la diferencia entre una rama `release` y una `hotfix`?
   R: `release` prepara una versión desde `develop`; `hotfix` corrige urgentemente desde `main`.

4. ¿Qué rama es la única requerida en GitHub Flow?
   R: `main`.

5. ¿Cómo se integran los cambios en GitHub Flow?
   R: Mediante Pull Requests que se revisan y fusionan a `main`.

6. ¿Qué añade GitLab Flow respecto a GitHub Flow?
   R: Ramas de entorno (`production`, `staging`) y feature flags.

7. ¿Qué es Trunk-Based Development?
   R: Estrategia con ramas de vida corta y fusiones frecuentes al tronco (`main`).

8. ¿Cuándo es recomendable usar Git Flow?
   R: En proyectos con versiones fijas y ciclos de release definidos.

9. ¿Qué es `git flow init`?
   R: Comando de la extensión `git-flow` que configura la estructura de ramas.

10. ¿Por qué es importante una convención de nomenclatura de ramas?
    R: Para identificar rápidamente el propósito de cada rama y mantener orden.
